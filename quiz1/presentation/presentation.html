01 · WHAT IS ARC-AGI?

A benchmark for
completely new problems.

ARC-AGI evaluates whether an AI system can solve reasoning problems it has never seen. It is not primarily testing memorization, factual knowledge or language understanding, but fluid intelligence: looking at a few examples, discovering the abstract rule behind them and applying it to a new situation.

“
Examples → Infer an abstract rule → Apply it to a new input
— The central idea of ARC

01 · WHAT IS ARC-AGI?

Not memorization,
skill acquisition

01

Unique tasks

Every ARC task is designed to be different, so solutions cannot be memorized task by task.

02

New skills

The goal is a system that acquires a new skill rapidly when it meets a new problem.

03

Efficiency

Brute force may eventually find an answer, but exhaustive computation is not evidence of general intelligence.

01 · WHAT IS ARC-AGI?

The second
generation

ARC-AGI-2 keeps the input–output grid format of ARC-AGI, but introduces harder tasks designed specifically to challenge modern reasoning systems. These elementary concepts matter because ARC tries to separate reasoning ability from specialized knowledge.

“
Can an AI efficiently infer a new abstract skill and use it on a problem it has never encountered?
— The real question behind the benchmark

02 · HOW A TASK WORKS

Training examples,
then a hidden test

Every ARC-AGI-2 task is a small reasoning problem made of colored grids. A few demonstration pairs show the hidden transformation; then a new input arrives and the correct output is hidden. The solver has to generate the complete output grid.

“
Input 1 → Output 1
Input 2 → Output 2
Input 3 → Output 3
New Input → ?
— Structure of a single task

02 · HOW A TASK WORKS

The rule is never given

The AI has to infer which objects exist, which properties are relevant, what changed between input and output, which transformations were applied, in which order and under which conditions. The inferred rule must explain all the training examples.

“
f(Input₁) = Output₁
f(Input₂) = Output₂
f(Test) = Prediction
— Discover the unknown transformation f

02 · HOW A TASK WORKS

Anatomy of a grid

01

0 – 9

Cells hold integers from 0 to 9, conventionally shown as colors so humans can read the task.

02

Up to 30×30

Dimensions vary between tasks, and the output does not necessarily match the size of the input.

03

No options

This is not a multiple-choice problem: the solver constructs the whole output grid itself.

03 · DATASET

1000 tasks to
build the system

The Training Set is intentionally not difficulty-calibrated: it ranges from simple to very hard. Its purpose is to expose the system to ARC's format and its Core Knowledge Priors, not to measure final performance. We can inspect these tasks and their solutions freely.

“
Learn reusable reasoning mechanisms, not the answers themselves.
— Not a conventional supervised dataset

03 · DATASET

Three evaluation sets

120 TASKS

Public

Public but for evaluation, not training. Human-calibrated: every task was solved pass@2 by at least two people.

120 TASKS

Semi-Private

Hidden from competitors; used for the live Kaggle and ARC Prize leaderboards. May have had limited exposure to third parties.

120 TASKS

Private

The most protected set, used for the final leaderboard. Not exposed to third parties: the strongest test of real generalization.

03 · DATASET

Two meanings of
“training”

At dataset level, the Public Training Set is 1000 complete ARC tasks used to develop our solver. At task level, "train" is the handful of demonstration input–output pairs stored inside one single task, next to its "test" input.

“
1000 tasks to build the solver.
A few examples to solve each task.
— Dataset level vs. task level

04 · RULES

How the scoring works

01

Pass@2

Two predicted grids per test input. The task counts as solved if either one matches exactly — the same bar used to calibrate humans.

02

Efficiency counts

Log-linear scaling from bigger models is not enough to beat ARC-AGI-2. Cost becomes a primary metric alongside accuracy.

03

Two leaderboards

Semi-Private drives the live Kaggle / ARC Prize leaderboard; Private decides the final ranking, so overfitting to public tasks does not pay off.

04 · EVALUATION

Hard for AI,
solvable by humans

The Public, Semi-Private and Private sets were built so that their human-facing difficulty distributions are statistically similar. More than 400 participants took part in the calibration process. A solver can understand a task partially and still get no credit at all.

“
100% of the final tasks were solved by at least two humans in fewer than two attempts.
— ARC-AGI-2 official page

05 · DIFFICULTY

Why is ARC-AGI-2 difficult?

01

Compositional

Several interacting rules at once, instead of one single transformation such as “move all objects downward”.

02

Multi-step

Transformations are sequential: the state produced by one operation decides what must happen next.

03

Contextual

Red border → move left; blue border → move right. The hard part is discovering when each rule applies.

05 · DIFFICULTY

One task, many operations

  1. 1
    DetectFind the objects and identify their shapes.
  2. 2
    CropIsolate the relevant region of the grid.
  3. 3
    MatchResize the objects and pair them with their shapes.
  4. 4
    PlacePut every object in its new position.

05 · DIFFICULTY

Beyond visual patterns

01

Symbols

A shape may encode a number, a direction or a category. Its meaning is defined by the task itself and must be inferred on the fly.

02

Novelty

Tasks are deliberately unique, so learned shortcuts stop working: “what is happening here?” replaces “have I seen this before?”.

03

No brute force

Tasks solvable by naïve program search were removed. The benchmark measures efficient abstraction, not raw computation.
